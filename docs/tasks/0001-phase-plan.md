## Legend

- **Parallel group (PG):** tasks in the same group touch disjoint writable files and may run concurrently, once their dependencies are done.
- **Shared generated files:** `openapi/v1.json` and `web/src/api/schema.d.ts` are regenerated by any API-changing task. Parallel API tasks merge **one at a time**, regenerate both files after rebasing, and never hand-edit them.
- **Standard gates:**
  - **Backend:** `dotnet restore; dotnet build -c Release; dotnet test -c Release`. Locally this needs LocalDB or a local SQL Server (no Docker).
  - **Frontend** (from `web/`): `npm ci; npm run lint; npm run build; npm run test`
  - **E2E** (from `web/`): `npx playwright test`

## Phase 5 – Deployment (requires explicit user approval)

- **Azure resources:**
  - App Service with a system-assigned Managed Identity
  - Azure SQL, with the identity as database user
  - **Storage account** (StorageV2, LRS, HTTPS only, TLS 1.2 or later)
    - container `catalog-images` (anonymous blob-level read, listing disabled; Q-13 approved 2026-11-06)
    - container `dataprotection-keys` (private); no other container is public
    - the non-production account is provisioned by the user (D-12); production provisioning still needs explicit approval
    - role assignment *Storage Blob Data Contributor* for the App Service identity
  - Key Vault (optional)
- **App settings:** `Storage:Images:*`, `Catalog:LowStockThreshold`, `Store:PublicBaseUrl`. Data Protection keys are persisted to Blob.
  - Also set `ASPNETCORE_FORWARDEDHEADERS_ENABLED=true`, with access restrictions so the app is reachable only through the App Service front end (otherwise `X-Forwarded-For` can be spoofed and the rate limit bypassed).
  - Optional: `RateLimiting__PublicPerMinute` (default 120), `RateLimiting__AuthPerMinute` (default 5), `Sitemap__MaxUrls` (default and maximum 50000).
- **Pipeline:** `deploy.yml` with OIDC, GitHub Environments and required reviewers, plus an approved migration step.
- **First admin:** `bootstrap-admin` against production only with user approval.
- **No production deployment, production migration, or production authentication configuration without explicit user approval.**
